# S3 — CodeArts plugin → scanner-binary → /guard/evaluate hop table, per OS

All citations are `file:line` at PR #13388 head **`eeec7e101e`** (0 behind `main`). This is a **source-derived** table — no host is needed to establish it; the resolution methods are read directly from the code, not inferred.

Config home is **homedir-anchored on every OS** — `GetConfigDir(homeDir) = filepath.Join(homeDir, ".codeartsdoer")` (`scanner/internal/agents/codearts/constants.go:28-30`), chosen because under an MDM root sweep the scanner process env is not the target user's, so the home dir is the only reliable anchor (comment `constants.go:21-27`). `filepath.Join` emits the OS-native separator, so the same code yields `~/.codeartsdoer/...` on Linux/macOS and `%USERPROFILE%\.codeartsdoer\...` on Windows.

## Scope note (grounds the external / owner buckets — NOT a decision)
- **Guard install + runtime lane is NOT OS-gated.** `codearts_install.go` registers the command unconditionally (`init` `:164-184`) and its `RunE` has **no** `runtime.GOOS` gate (`grep` = none) — so the Windows `.exe`/AV-retry and macOS atomic-inode branches above are real code that runs on those OSes (and is unit-green on CI's macOS/Windows runners), but has **not** been driven on a real macOS/Windows host from this Linux box (bucket b).
- **Only DSL *discovery* is Linux-only, by design.** `scanner/tools/dsl_agents/codearts.py:99-107` — `build(target_os)` returns `None` unless `target_os == "linux"`. That gates posture *detection*, not the guard install/runtime hops tabled above.
- The **gate-vs-prove decision** (make `install codearts` + the runtime-protection claim Linux-only, or require real macOS/Windows chain runs) is the **owner's** (bucket a) — this table supplies the facts, it does not answer it.
