inventory row transitions to is_deleted=TRUE, for (1) the AGENT row, (2) a SKILL
row, and (3) the builtin TOOL rows.

is_deleted=true transition does not exist in this lane's code for any of the
three entity kinds.

WHY (code-grounded; triple-confirmed by reading the lane + an independent code
sweep + the prior tenant-A live run c2-uninstall-psql.txt):

  * The ONLY rescan-driven soft-delete in the whole CodeArts/OpenCode desktop-
    agent ingestion path operates on asset_connections rows of type AGENT_TO_MCP
    (and AGENT_TO_MODEL), scoped by (source_asset_id, connection_type), via
    AssetConnectionRepository.soft_delete_old_connections
      backend_python/src/common/repository/asset_connection.py:752
      driven from endpoint_asset_ingestion/ingestion/mcp_writer.py:1661
      (activity mcp_asset_creation/activities.py:1643).
    An EMPTY keep-set is deliberately SKIPPED (mcp_writer.py:1696-1708) — an
    MCP-less/absent payload is treated as "no signal", never "delete everything".

  * The parent desktop-agent asset (app_definition_id=endpoint_codearts) is only
    ever UPSERTED + last-seen-touched (touch_agent_last_seen,
    desktop_agent_creator/activities.py:3301). It is NEVER soft-deleted by scan
    absence. Asset-level is_deleted=true is set ONLY on identity-migration /
    placeholder-merge paths (activities.py:1571, 1829), not on "no longer
    scanned". When the agent is undetected, NO agent payload is sent, so nothing
    processes it and the row persists last-known-good.

  * Builtin tools are UPSERT-ONLY: create_builtin_tools (activities.py:2790)
    calls only ToolRepository.upsert_tools_bulk. deactivate_tools_not_in_list
    (tools.py:665) is NEVER called for BUILTIN_AGENT_TOOL rows on a desktop
    agent. The `tools` table has NO is_deleted column at all (only is_active /
    source_enabled) — verified below.

  * Skills are ADDITIVE-ONLY: skills_creation/activities.py:446 upserts skill
    assets (insert-only) + AGENT_TO_SKILL edges. There is NO deactivate / soft-
    delete / keep-set step for skills anywhere in the scanner lane, so a removed
    SKILL.md flips neither the skill asset nor its AGENT_TO_SKILL edge.

The real, provable rescan lifecycle signal for this lane is the AGENT_TO_MCP
connection-EDGE soft-delete (agent present, >=1 MCP still reported, a previously-
seen MCP absent) — proven on the live DB in c2-uninstall-psql.txt (tenant A,
edge id 1441 is_deleted f->t). That is an EDGE transition, not an inventory-row
(asset/tool) is_deleted transition, and it is none of the three kinds this item
asks for.
