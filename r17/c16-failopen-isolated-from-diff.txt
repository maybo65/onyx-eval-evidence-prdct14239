--- 4. Conclusion ---
CodeArts is Huawei's rebranded OpenCode distribution. This PR wires CodeArts to
resolve MCP identity through OpenCode's own opencodeidentity.Resolve (the shared
`case types.SourceOpenCode, types.SourceCodeArts` branch above), and installs a
CodeArts plugin that is byte-identical to the OpenCode plugin except `--source`.
The dispatcher fail-open (a `tool_call`/`tool_search`/`tool_describe` meta-tool
carrying the real MCP id in tool_params.id, which the tool_name-only reader maps
to `unresolved_prefix` -> sanction skipped) is therefore a property of the
UNCHANGED OpenCode resolver, inherited by CodeArts by construction. It is not
introduced, widened, or altered by this diff. Round-17 direct-name captures
(rows 4/5) further show the SAME lane enforces correctly when identity resolves
(ENABLE_TOOL_LAZY_LOADING=false), so the gap is specifically the dispatcher
dispatch shape, not the agent. Fix (owner's call, documented not committed):
resolve identity from tool_params.id when tool_name is a dispatcher meta-tool —
a change to opencodeidentity/resolve.go that would benefit OpenCode and CodeArts
alike, precisely because they share this resolver.
